## 0. 结论与使用方法

沿用“可靠性 → 窗口和观察 → 只读语义 → 语义动作与事件 → 完整验收”的顺序。同时，从第一阶段并行开展一个只读 AT-SPI 可行性验证，尽早暴露应用归属与私有总线问题。

第一项正式交付不是大而全的语义服务，而是：**一个真实 GUI 中能执行、能接管、不会重放过期动作的完整操作闭环**。

这份文档给开发 Agent 使用。先核对本地工作树，再将设计拆成可审查的小提交。本文中的新增模块名、RPC、状态、文件路径和命令形状均为设计建议，不得在未实现前写入“当前已支持”清单。

## 1. 产品合同

AgentSeat 为一个被封装的应用实例及其可确认归属的窗口提供：受限输入、视觉观察、可选 UI 语义、状态变化和人类接管。规划、模型选择、任务拆解、业务授权和多 Agent 调度由外部系统负责。

保留现有单应用微型合成器，不更换用户桌面，不引入完整嵌套桌面、虚拟机或 VNC。原生 Wayland 为主，私有 XWayland 为兼容通道。

### 1.1 人机协作的准确含义

人类在宿主其他应用里工作时，Agent 可以操作被封装应用而不抢宿主焦点、鼠标或剪贴板。人类进入同一个被封装应用操作时，由人类优先接管，Agent 暂停并重新观察。

本轮不承诺同一个普通应用里，人和 Agent 同时拥有两份独立的插入光标、选区、编辑状态或表单事务。多设备、多个协议对象、多个视觉指针，都不能代替真实双焦点兼容性证明。[S1][S4]

### 1.2 隔离边界

运行时保证自己的已授权控制路径不随意扩展到宿主应用。它不是文件系统、网络、进程或同 UID 恶意程序安全沙箱。应用仍可能凭自身权限读文件、访问网络或请求其他程序提供服务。[S1]

`session_id` 是身份防串线，不是认证凭证；0700/0600 和同 UID 校验也不能阻止该 UID 下任意恶意代码。对运行时的约束，不能夸大成对被封装应用一切下游副作用的约束。

### 1.3 本轮不纳入核心

全局 Desktop Backend、Portal/libei 桌面遥控、CDP/PTY 意图路由、模型循环、每个应用的专用驱动、多 Agent 同时写同一应用、真正的文件与网络沙箱均不作为本轮前置项目。以后可以通过外部系统组合，但不要现在建设另一套平台。

## 2. 已核实的公开基线问题

以下为静态源码判断，不冒充真实机器上的复现记录。

| 项目 | 公开代码证据 | 实施要求 |
|---|---|---|
| 主循环可能被客户端拖住 | `run_server → handle_client → read_line_fd/write_all` 同步处理连接 | 非阻塞读写、半包超时、输出背压、连接预算；慢客户端不得占住仲裁 |
| 长文本阻塞 | `keyboard.type` 调用带 sleep 的同步输入循环；常规 flush 位于循环后 | 可取消增量任务；每个有界片段实际提交事件 |
| 人类活动只是宽限计时 | daemon 收活动报文后更新到期时间；合成器区分真实/虚拟输入并上报 | 最终投递入口应能阻断旧虚拟输入，不能只在发送前检查 |
| 释放可能受普通输入门禁影响 | `pointer.button` 和 `keyboard.key` 先检查 active/focus | 建立只释放当前 Agent 已持有输入的受限清理路径 |
| 窗口列表是假抽象 | daemon 使用单一 `agentseat:root`；focus 改本地字段 | 改成微型合成器实际报告；未实现的操作明确返回不支持 |
| move/resize 存在成功假象 | 同一 dispatch 分支返回结果但没有对应实现 | 禁止成功空操作；真实实现必须返回合成器确认 |
| 会话身份未覆盖写操作 | `response_for` 转发请求；未见通用 expected-session 校验 | 服务端统一验证所有写请求，不依赖客户端先 heartbeat |
| 截图高频链路冗余 | 每次 observe 固定 4 次 grim；显式 sleep 合计 360ms | 先改请求驱动的单次完成捕获，再考虑复用与协议迁移 |
| 读取带隐式维护/聚焦风险 | `observe` 调 `sync_window_tree`；status/heartbeat 有尺寸协调 | 观察只读；几何协调移到独立事件处理路径 |
| 历史清理范围问题，本地已有收窄 | 当前 `daemon_belongs_to_runtime` 校验控制 socket；microhost 校验 runtime 环境 | 保留本地修复；回归两个实例、旧 PID 和资源替换，不重复按公开旧版改造 |
| 人类 IME 被一并影响 | 启动器设置 simple/空 IM module 和 `@im=none` | 早期验证真实人类中文输入，不把 Agent 粘贴当成 IME 支持 |
| JSON-RPC 错误形状不标准 | 声明 2.0，但 `error.code` 为字符串 | 新协议用整数 code，机器可读类别移到 `error.data.kind` |

源码对应：[S2][S3][S4][S5]。其中截图 sleep 数量可以由代码计算，但总延迟、CPU、内存和影响频率必须实测。

## 3. 最小架构与状态主权

```text
外部 Coding Agent / pi / 其他执行器
                 │
           CLI / SDK / 可选 MCP
                 │  同一份公开协议
                 ▼
           agentseatd
    请求身份、写租约、操作生命周期、回执
       │                       │
       │                       └─ 按需语义 worker
       │                          AT-SPI、受限查询、语义动作
       ▼
  现有单应用微型合成器
  真实窗口/焦点/几何、人类活动、输入最终门禁、帧状态
       │
  被封装应用和可确认归属的子窗口
```

不要把每个方框实现成一个长期独立 daemon。先保留现有原生 daemon 和微型合成器。语义 worker 作为可选组件，仅在需要隔离慢调用时启用；在一个活跃会话中复用，不为每个节点、每次请求创建进程。

### 3.1 真实状态只能有一个来源

微型合成器负责：真实 surface/window、实际焦点、输出布局、物理/虚拟输入来源、最终输入门禁、人类接管发生顺序。

`agentseatd` 负责：控制者身份、写租约、操作队列、取消请求、回执与公开协议。它保存合成器状态的带版本投影，不通过更新自己的一段 JSON 来假装窗口操作已执行。

语义 worker 负责：给定应用范围内的节点发现、AT-SPI 缓存和调用。它不自行扩大范围，不单独授予写权限，也不在主 daemon 无响应时自行决定继续执行。

### 3.2 内部 IPC

用本地、版本化、带会话身份的内部通道连接微型合成器和 daemon。优先复用现有 Unix socket 和事件循环；不要为此加入 HTTP 服务、数据库或消息队列。

事件至少包含事件序号、会话身份、当前控制代际、窗口/几何更新。启动时请求完整状态，正常时增量更新；检测到事件缺口后重建状态。内部通道断开时，Agent 写权限进入不可用状态，但不要因此未经授权重启或销毁应用。

## 4. 不变量

### I1：写请求不串会话

每个改变应用状态的请求在服务端执行前验证不可变 `session_id`。会话替换、daemon 重建或显式重启产生新身份。旧请求不能因默认 socket 指向新会话而继续执行。

### I2：一个应用范围只有一个有效写者

允许多个观察者。写入由明确控制者持有的租约授权；转交时使旧授权失效。会话可以在 CLI 退出后存续，但这不等于任何新连接自动成为写者。

### I3：接管后旧计划失效

人类接管、显式暂停、控制权撤销等事件更新 `control_epoch`。旧 epoch 的待执行动作作废。宽限时间过去只意味着可以重新申请操作，不意味着可以重放队列。

不要求每次鼠标移动都产生新 epoch；在接管边界更新，连续活动只延长占用。只有封装应用内的实际人类活动触发这个规则，不因用户在宿主其他软件打字而暂停所有 Agent。

### I4：能停是最终投递属性

daemon 的发送前检查不够：输入可能已经排入 Wayland 连接。微型合成器最终投递虚拟事件前也要检查有效授权/来源代际，并能丢弃撤销后的旧事件。

标准虚拟输入事件不天然携带每个动作的 epoch。实施者必须选择并测试具体机制，例如在撤销时废弃旧输入设备/连接并重新授予新一代设备，或使用可关联代际的受控内部投递路径。不能只在 RPC JSON 中加字段，却让合成器无法辨认旧事件。

### I5：释放不能被拒绝成卡键

停止新的 Agent 输入后，允许受限清理它已经按下的键和按钮。清理只能作用于 Agent 自己持有的状态，不释放人类仍按着的 Ctrl、Shift 或鼠标。

普通未经授权客户端不能利用“清理豁免”构造新操作。由运行时内部所有权账本产生释放事件，必要时为当前持有者提供 release-only 通道。

### I6：回执不冒充结果

“请求接受”“事件投递”“应用接口回复”“后置状态确认”是不同阶段。超时、调用结果未知、部分副作用、取消后仍有在途调用，都必须真实表达。

### I7：观察不接管应用

观察、状态查询和只读语义查询不主动聚焦、滚动、输入、建立新写租约或启动另一个应用。按需启动私有语义基础设施不是 GUI 写入，但必须在诊断中披露。

### I8：范围不随故障扩大

AT-SPI 无法确认归属、窗口无法映射、跨总线节点未知时，返回部分或不可用。不能为提高覆盖率，自动扩大为整个宿主桌面。

### I9：所有等待和资源有界

RPC 半包、动作队列、语义树遍历、慢客户端、帧缓冲、事件积压、截图导出、辅助进程均有可配置上限或生命周期。达到上限时返回明确状态，不忙等，也不静默截断成完整结果。

### I10：技术控制不替模型做业务判断

运行时负责身份、范围、类型、能力、时序和副作用状态。它不在内部增加 LLM，不用关键词规则猜“保存”“购买”“删除”的业务意义。外部 Agent 根据用户目标选择通道与后置条件。

## 5. 请求、观察与身份合同

### 5.1 必要标识

| 字段 | 解决的问题 | 生命周期 |
|---|---|---|
| `session_id` | 不能操作后来替换的新应用会话 | 会话 |
| `control_epoch` | 人类接管或控制权转交后，旧动作作废 | 一次有效控制阶段 |
| `controller_id` / 写租约 | 多调用者不能交错写入 | 控制者的授权期 |
| `request_id` | 断线重试不重复提交同一操作 | 会话内有界去重窗口 |
| `window_id` | 标识合成器真实窗口实例 | create 到 destroy |
| `geometry_version` | 不使用已失效的几何映射 | 一份坐标变换 |
| `frame_id` | 引用某次已完成的捕获 | 帧资源有效期 |
| `node_ref` | 引用已核验范围和代际的语义对象 | 对象与 bridge/bus 代际 |
| `event_seq` | 事件恢复、缺口检测 | 会话事件流 |

这些标识不是每次都全传。语义动作使用节点身份；坐标动作使用帧和变换；SDK 可以绑定不变的会话和控制者信息。不要让模型为了点击一次手工拼装全部底层元数据。

### 5.2 观察不是跨协议原子快照

图像和 AT-SPI 来自不同数据源。给出各自单调时钟时间戳、范围和版本，不宣称两者在同一个 CPU 时刻产生。合并观察可标记 `consistent`、`changed_during_capture`、`partial`，必要时返回需要重新观察。

建议输出形状，字段名称可在 ADR 中冻结：

```json
{
  "session_id": "s-…",
  "observation_id": "o-…",
  "control_epoch": 17,
  "window_id": "w-…",
  "geometry_version": 31,
  "visual": {
    "status": "available",
    "frame_id": "f-…",
    "captured_at_monotonic_ns": 123456789,
    "pixel_size": [1600, 1000],
    "logical_size": [1280, 800],
    "content_rect": [0, 0, 1600, 1000],
    "resource": "frame:…"
  },
  "semantic": {
    "status": "partial",
    "observed_at_monotonic_ns": 123456800,
    "scope_id": "scope-…",
    "truncated": true,
    "next_cursor": "cursor-…"
  }
}
```

示例数字仅说明格式，不代表当前设备配置或测量。

### 5.3 动作协议

公开接口可以保持少量高层动作，再映射到现有底层 RPC：

```json
{
  "jsonrpc": "2.0",
  "id": 19,
  "method": "act.submit",
  "params": {
    "session_id": "s-…",
    "controller_id": "c-…",
    "control_epoch": 17,
    "request_id": "req-…",
    "action": {
      "kind": "pointer.click",
      "target": {
        "window_id": "w-…",
        "frame_id": "f-…",
        "geometry_version": 31,
        "coordinate_space": "frame-normalized",
        "x": 0.45,
        "y": 0.62
      },
      "button": "left"
    }
  }
}
```

新增接口是设计，不是当前可用命令。对 bool、字符串假装数字、NaN、Infinity、越界坐标、无效 Unicode、错误窗口身份做严格校验。错误不能被转换成默认点击位置。

### 5.4 JSON-RPC 与错误

采用标准 JSON-RPC 2.0 外形，`error.code` 为整数。[S15]稳定机器类别放在 `error.data.kind`，人类 message 可本地化。例如：

```json
{
  "jsonrpc": "2.0",
  "id": 19,
  "error": {
    "code": -32001,
    "message": "控制权已变化，需要重新观察。",
    "data": {
      "kind": "STALE_CONTROL",
      "current_control_epoch": 18,
      "retry_mode": "reobserve"
    }
  }
}
```

建议错误类别：`SESSION_MISMATCH`、`STALE_CONTROL`、`NO_WRITE_LEASE`、`HUMAN_ACTIVE`、`STALE_GEOMETRY`、`STALE_NODE`、`SCOPE_UNVERIFIED`、`OUT_OF_SCOPE`、`CAPABILITY_UNAVAILABLE`、`UNSUPPORTED`、`BUSY`、`RESOURCE_LIMIT`、`EVENT_GAP`、`REQUEST_ID_CONFLICT`。

结果不明通常是操作回执状态，不要仅以可重试错误表达。

## 6. 输入仲裁与操作生命周期

### 6.1 非阻塞主循环

接受连接、解析半包、写响应都必须有界。断开的读端不能通过 SIGPIPE 使 daemon 意外退出。连接数、单请求大小、输出队列和每轮处理量要有上限。控制/接管事件不能被普通 RPC 洪水饿死。

不要把“把 socket 改成 nonblocking”当成全部实现：还需要每连接解析状态、超时、部分写入续传、公平调度、错误清理。无待处理截止时间时，避免仅为轮询而周期唤醒。

### 6.2 高层操作

将 `click`、`double_click`、`key_chord`、`type_text`、`pointer_drag` 做成有明确边界的操作。不要让外部模型自行拼凑不受保护的 press/release 序列。

`pointer_drag` 仅指按住按钮移动再释放。跨应用数据拖放、剪贴板文件传输是另一项能力，不因有拖动轨迹就宣称支持。

长文本按有界片段或字符任务执行，片段之间返回事件循环。实际刷新输入事件，别在 sleep 完后才一次性批量 flush。暂停时立即终止未投递部分。

### 6.3 状态模型

内部可采用：

```text
accepted → running → finished
         ↘ cancelled_before_dispatch
running  → cancel_requested → cancelled / partial / outcome_unknown
```

回执分离三类信息：

```json
{
  "operation_id": "op-…",
  "execution": "finished",
  "effect": "partial",
  "verification": "not_requested",
  "replay_safe": false,
  "requires_observation": true
}
```

上面的状态不是四处散落的 bool；在一个模块里定义合法转换并测试。

### 6.4 取消与释放的细节

按键释放本身也可能完成一次点击、拖放或应用动作。取消不等于事务回滚。运行时只承诺停止尚未投递的动作、清理自身输入状态、如实报告可能发生的副作用。

真实人类和虚拟设备共用应用 seat 时，要测试双方同时按同一个修饰键的场景。清理 Agent 状态不能损坏人类设备状态；客户端切换焦点后的 pressed-state 同步也要测试。

### 6.5 客户端断开不等于应用退出

会话、写租约、单次操作、单条 RPC 连接是不同生命周期。正常短命令的连接关闭不能停止 GUI。

对于 `act.submit` 已接受的有界高层操作，是否在客户端断开后继续必须有唯一明确规则。建议由会话内操作对象和截止时间管理，允许重连查询；不因提交响应后连接关闭就撤销。裸 key-down、持有按钮等低层输入只能在可续约的输入租约内存在，拥有明确的最大持有期和清理机制。

不能同时实现“每次 RPC 退出就释放所有输入”和“用多个短 CLI 完成拖动”；两者语义冲突。

### 6.6 重试与去重

同一 session/controller 下的相同 `request_id`、相同规范化参数，返回同一个操作记录；相同 ID 不同参数返回冲突。去重记录有边界和过期行为。

daemon 崩溃之后不能仅凭内存去重宣称 exactly-once。会话重建产生新身份；旧操作结果未知时，由外部 Agent 重观察决定下一步，不自动重放。

## 7. 窗口、焦点与坐标

### 7.1 真窗口注册

由微型合成器为真实窗口分配 session-local ID，报告创建、映射、取消映射、销毁、父子/弹窗关系、窗口几何、实际焦点和适用的 modal/grab 状态。不要使用标题、app_id 或可复用的裸指针作为唯一身份。

窗口对象和 surface 对象可以在内部区分，但对外只暴露 Agent 完成任务需要的层次。弹窗可能不是普通 toplevel，不能只遍历 toplevel 就认为应用树完整。

`window.focus` 必须驱动并确认实际焦点变化，且经过人类优先门禁。move/resize 可先返回不支持；不要为了接口齐全写假成功。

### 7.2 当前单实例行为

保留本地已有默认会话及命名多实例接口，不退回单实例产品行为。逐项验收独立资源命名、同时运行及互不清理；未通过的组合在能力报告中标为未验证。

测试“同名宿主应用 + 一个封装实例”不依赖多实例特性，必须早期完成。本地命名多实例已存在，因此两个封装实例的同时运行和独立停止是本轮必测项，不能用更换一个 runtime 目录就假定安全。

### 7.3 统一变换

以微型合成器输出逻辑坐标作为内部基准。分别保存：应用 surface、私有输出逻辑、原始捕获像素、裁剪/缩放后的模型图像、宿主窗口显示之间的变换。

每张图明确尺寸、裁剪区域、缩放、padding/letterbox、方向及变换版本。坐标动作引用它所看的那一帧；由运行时转换，避免模型重复手算。

AT-SPI 的 Component 接口允许选择不同坐标系，工具包实现也可能不同。[S8] 所以 bounds 必须带来源坐标空间和映射状态。无法确认映射时返回 `bounds_unmapped`，不拿它盲点；在范围确认且支持直接语义动作的情况下，语义动作仍可独立可用。

### 7.4 过期判断

窗口移动/缩放、输出尺度变化、裁剪方式改变更新 `geometry_version`。人类接管更新 `control_epoch`。窗口替换和节点重建更新对象代际。

不要因时钟、闪烁光标或视频每一帧变化就强制所有动作失效。根据目标相关前置条件判断；几何有效不代表 UI 语义必然没变，动画变化也不必然使一个已确认按钮失效。

## 8. 视觉观察：复用连接，按需捕获

### 8.1 先修现有协议路径

先删除固定四次捕获和固定 sleep，以真实捕获完成事件为准。一次 observe 只保留一次成功捕获结果；发生可解释的失败时才有限重试，并披露重试次数。

在非活动工作区，需要微型合成器能够按观察需求推进必要帧，不能为了截图切换宿主工作区，也不能强制所有应用永远全帧渲染。

HUD 的动画不是应用状态。默认不让装饰性 HUD 决定截图等待时长，必要时允许捕获不含 HUD 的应用场景。

### 8.2 然后复用

常驻或可复用的捕获连接、有限缓冲池、按请求编码、按需导出。没有观察/订阅消费者时，不为 AgentSeat 自身持续编码、写 PNG 或输出视频。

复用优先实现简单可靠的内存缓冲；DMA-BUF、零拷贝、更多渲染后端仅在基线证实值得做时加入。缓冲资源需要 frame_id、大小、格式、stride、生命周期和慢消费者背压；不能把可被下一帧覆盖的内存伪装成稳定快照。

### 8.3 “现在的帧”和“下一次变化”分开

- `snapshot`：返回当前可用且满足新鲜度要求的完整帧；未变化可以复用，但保留真实捕获时间并标记复用。
- `wait_for_change`：等待指定 frame/revision 之后的变化，有截止时间和取消机制。

新的 ext-image-copy-capture 协议在首次成功帧后允许等待内容变化再复制；这可能无限等待。[S12] 因此不能直接把“下一次变化”实现当作每次 snapshot，否则静态窗口会成为超时案例。

捕获完成只证明获得了图像，不证明页面加载完成或操作成功。damage 是像素变化证据，不是任务完成条件。

### 8.4 协议迁移

对外观察协议不绑定 wlr-screencopy 或 ext-image-copy-capture。后端能力通过运行时协商。新协议的 ready、damage、presentation time 可利用，但迁移单独提交、单独比较；不延误仲裁与范围修复。[S12]

## 9. AT-SPI：先验证范围，再做只读桥

### 9.1 两条总线不要混淆

session D-Bus 与 accessibility D-Bus 不同。常见发现过程是在 session bus 上调用 `org.a11y.Bus.GetAddress`，随后连接返回的 accessibility bus；AT-SPI Registry 在后者上。[S6]

因此私有 Wayland display 不自动产生私有 AT-SPI 范围，单独执行 `dbus-run-session` 也不能代替实际确认应用、Registry 和 bridge 使用的是哪条 accessibility bus。

### 9.2 推荐路线

为 AgentSeat 会话设计可选私有 session/a11y 总线运行环境，bridge 与应用均显式进入对应范围，并核查工具包实际注册结果。不要假设仅改环境变量就覆盖所有 toolkit、D-Bus 激活和单实例机制。

优先证明这条路线在目标 GTK、Qt 和 Chromium/Electron 上可用，再决定正式默认值。若某应用需要共享宿主服务，单独记录需求；不要为了兼容，把 bridge 自动回退到扫描整个宿主。

共享宿主总线的受限发现可作为明确标记的兼容模式，但只在应用归属可确认时使用；它不提供与真正私有总线同等的发现隔离。

### 9.3 总线生命周期属于会话

`dbus-run-session` 的总线生命周期跟随它直接运行的 PROGRAM。[S11] 应用启动器可能很快退出而 GUI 继续存活，所以不能把私有总线绑到启动器退出上。由会话存活锚点或 supervisor 管理，直到应用会话真正结束。

不要改写宿主 systemd/D-Bus activation 全局环境。检查继承的总线地址、X11 发现路径、用户服务激活是否指向宿主。新建总线和 Registry 也计入轻量性基准。

### 9.4 应用归属的证据链

使用启动记录、受控进程生命周期、总线连接凭证、已映射私有窗口与可验证的应用关系共同建立 `ApplicationScope`。cgroup 若用于生命周期归集，不因此被当作权限沙箱。

D-Bus 可以返回连接的 UID/PID，以及在实现支持时返回 ProcessFD；PID 可能复用，需结合生命周期或可用 pidfd。[S7]

不能仅凭 app_id、标题、可执行文件名、最初启动器 PID 或同 UID 认定归属。共享进程可能承载多个窗口/实例，XWayland surface 的客户端也不能简单等同于每个原生 X11 应用进程。

跨进程可访问子树、embedded 节点和新总线 owner 必须重新核验；不能根节点合规就无条件信任所有引用。

### 9.5 启动逃逸与外部对话框

单实例软件可能把请求转交给宿主已有进程；Portal 文件选择器、认证窗口或链接处理器也可能由范围外服务提供。诊断并返回明确边界状态，不把它们通过标题匹配收编。

这可能要求使用应用明确支持的独立实例/profile 参数。参数必须根据该应用实际支持情况验证，不做全局强制的通用猜测。

### 9.6 第一批只读接口

```text
a11y.snapshot
a11y.query
a11y.get
```

节点按需提供 role、name、states、interfaces、actions、relations、bounds 及映射状态。文本全文与大文档表格按范围读取，不默认整棵树返回所有文本。

快照有深度、节点、字节、耗时和并发请求预算，并提供明确截断标志、原因与子树/分页继续方式。这是传输与可靠性预算，不是给模型硬设一个很小的上下文上限。

树可能动态重建，AccessibleId 也不代表永远可用的定位器。[S8] `node_ref` 为服务端维护的不透明引用；bridge/bus 重启、节点消失、owner 变化后失效。重查返回候选，不把同名新按钮无声替换成原操作目标。

### 9.7 worker 实现选择

继续使用现有 C/Python 技术栈。只读原型可以使用已有 AT-SPI 绑定；正式方案优先复用成熟库。需要从阻塞接口隔离时，使用一个可回收的 worker，设置调用截止时间和取消边界。

原型结束时选择并维护一条主实现路线，不长期保留两套不同语义的生产桥。主 daemon 和合成器不能同步等待大树查询。

工具包能力必须运行时探测。GTK 文档说明相关环境变量用于运行与调试且不保证 API 稳定，不能凭最新文档假定用户已安装版本相同。[S10]

## 10. 语义写入：与键鼠同一入口

第二批接口：

```text
a11y.perform
a11y.set_text
a11y.set_value
```

未来的 `grab_focus`、`scroll_to`、设置光标/选区、选择列表项，以及其他能改变应用状态的 AT-SPI 方法，也属于写操作，不能归入只读旁路。

### 10.1 调用流程

范围验证 → 节点有效性 → 实际支持接口/动作 → 当前控制授权 → 调用前最后检查 → 发起一次调用 → 记录调用结果 → 按需验证目标状态。

AT-SPI Action 按对象实际支持的 action index 调用，机器名称和本地化名称应区分；不能假定每个按钮都支持名字为 `click` 的动作。[S9]

`set_text` 与物理打字语义不同，可能绕过某些逐键行为或输入法过程。暴露明确通道，让外部 Agent 根据任务选择，并验证应用最终状态；不要自动认为语义写入一定等价于真人输入。[S9][S13]

### 10.2 在途调用不能假装撤销

通用 AT-SPI 调用发送给应用后，应用可能已经执行或稍后执行。关闭 worker、取消本地 future 或 D-Bus 超时，不证明应用动作没发生。

人类接管后停止所有未发送语义动作，标记已发送且未确认的调用为在途/结果不明，披露是否仍有未决写入。不要返回“已完全停止且绝无后续副作用”的错误承诺。

运行时可在调用前减少竞态窗口，但对于任意第三方应用，不能把跨进程检查与应用内部副作用包装成原子事务。

### 10.3 禁止结果不明时自动换通道重试

“保存”语义调用超时后，不能自动再坐标点击保存；“付款”超时后更不能自行补交。仅当确定没有投递、没有副作用且权限仍有效时，才允许有明确规则的回退；其余情况回到观察和上层决策。

## 11. 事件与条件等待

### 11.1 最小接口

```text
events.subscribe
events.read
wait
```

使用有界事件环和 `event_seq`。慢消费者可知道自己落后，但不能拖住输入和人类接管。重复的语义/几何更新可以按对象合并；接管、权限失效和终止等关键事件不能被普通更新静默淹没。

有缺口时返回 `EVENT_GAP`，提示重新获取对应状态，不编造没有发生过的增量。

### 11.2 等待目标状态，而非任意事件

AT-SPI 提供文本、状态、属性等事件，但事件只用于唤醒判断。[S14] 保存后等待的是指定窗口关闭、dirty 状态改变或外部约定的完成信号，不是“收到了任何一个事件”。

避免丢失唤醒：先建立事件关注并记下序号，再检查条件；处理事件后重新检查条件。支持立即满足、截止时间、取消、会话替换和桥重连。事件可能遗漏时，可在等待期间低频、有界地复查；没有等待者时不轮询整棵树。

不要要求所有应用稳定到“完全没有像素变化”。视频、进度指示、光标闪烁可能一直变化；应采用目标相关条件。

### 11.3 后置条件保持小型、结构化

只支持有限、可组合的谓词，例如窗口存在/消失、节点存在、状态满足、文本片段匹配、值等于/在范围内、几何版本变化。应用业务是否最终成功，由外部系统选择可验证条件；不要在 runtime 内加入自然语言任务裁判。

## 12. 人类输入法与 Unicode

公开启动器会为了 Agent 通道设置 simple/空 IM module。[S5] 这会同时影响人类编辑，必须提前验证。

分成两项能力：

1. Agent Unicode 输入：明确选择虚拟键盘或私有粘贴等通道，保证文本进入目标、按键释放、剪贴板范围正确。
2. 人类 IME：在封装应用里真实输入中文，验证 preedit、候选框、确认、撤销和焦点切换。

不能用 `agentseat type '中文'` 通过来证明第二项。

在阶段 0/1 记录现状，阶段 2 开始验证可行路线；未通过前不能发布“完整人机协作”。可以验证外层/内层 text-input 转发或经过确认的输入法连接方式，但具体实现按当前工具包与 compositor 能力决定，不预先承诺一种协议适配所有应用。

人类 preedit 活跃期间，Agent 不得插入干扰性文本。私有 Unicode 粘贴完成回执也应区分提供数据、应用请求数据、目标文本已确认，不能把 clipboard transfer 当作最终文本写入证明。

## 13. 性能与资源预算

### 13.1 基线测什么

记录系统、Hyprland/wlroots/工具包/图形驱动、分辨率与缩放、原生 Wayland/XWayland、HUD/语义开关和目标应用版本。

测冷启动和热路径：完整 click、按键组合、短/长文本、Unicode、observe、只读查询、语义操作、人类接管、重连。延迟至少报告 p50/p95/p99、样本数和失败率。

测整个会话进程树，不只统计主 daemon：CPU 时间、PSS/RSS、唤醒、子进程启动数、图像编码、落盘字节、缓冲峰值、事件积压、总线和 Registry 开销。

保持相同 workload 比较“应用单独运行”和“被 AgentSeat 封装”；动画应用自己的渲染负担不混算成 runtime 的空闲开销。

### 13.2 必须区分的时间点

```text
请求进入 → 校验完成 → 开始投递 → 投递完成
       → 应用可观测状态改变 → 新图像/语义证据可用
```

`version`、heartbeat 的往返不能代替完整 GUI 操作速度。

### 13.3 先有确定性成本门槛

目标不是先写没有依据的毫秒数。先建立这些可执行断言：常规热输入不启动 hyprctl/截图子进程；观察不固定四遍；无消费者时无 AgentSeat 引起的持续编码和落盘；慢语义查询不阻塞接管；事件、缓冲和队列有界。

阶段 0 结束时，把实际设备上的数字 SLO 与回归阈值写入基准配置；之后每个阶段持续比较，不能无限推迟量化验收。任何建议阈值必须标明“目标”，不能表述为当前成绩。

### 13.4 控制器与宿主桥

窗口布局/宿主移动等低频变化使用事件驱动协调。`hyprctl` 可以用于启动和必要诊断，但不要每个 move/click 重新查询宿主所有窗口。SDK 直接使用会话协议复用连接；CLI 作为人类入口允许短进程开销，但不应额外层层启动辅助工具。

## 14. 隐私、权限和日志

默认不记录 UI 文本、截图、输入文本或完整节点树。截图文件采用显式导出；回执默认只留阶段、长度、资源与错误信息。密码输入既不记明文，也不通过简单文本 hash 形成可猜测的日志。

在调用读取密码内容的方法之前，根据角色/状态和已知规则限制读取；不要先拿到再在最终输出里遮掉。事件 payload、缓存、debug dump 同样适用。对自绘界面或错误标注控件，不能承诺自动识别全部秘密。[S8]

图像观察本身仍可能包含敏感内容。语义字段过滤不等于图像自动脱敏；保证明确授权范围和不自动落盘，而不是宣称全自动隐私保险。

UI 文本、窗口标题和可访问描述均标为应用数据，不升级成系统指令。运行时只执行结构化、已授权动作，不解释 UI 文本中的 shell 命令。

读取路径、IPC socket、启动记录、PID 和清理路径需防止同会话替换竞态。不要凭扫描结果杀掉同名程序，避免用旧 PID 误杀复用后的进程。功能目录权限无法代替完整同 UID 威胁隔离；范围说明必须一致。

## 15. 面向 Agent 的最小使用体验

最终提供四个主动作：

```text
observe → act → wait → observe
```

再提供 `doctor`、`capabilities`、`pause/resume`、操作状态和取消。底层 AT-SPI 原语保留给高级调用者；不要把几十个底层方法一次性塞成模型必须掌握的工具集。

### 15.1 doctor

只诊断，不自动改宿主配置。报告实际后端、会话身份、范围验证、a11y 状态、坐标映射、捕获新鲜度、IME 已验证项、缺失依赖和具体退化原因。环境变量和总线信息要注意过滤敏感数据。

### 15.2 capabilities

区分“软件实现支持”“当前应用暴露”“本会话已授权”“实际可用”。例如 AT-SPI 全局支持不代表此窗口有可用节点；有节点不代表支持 set_text；有 bounds 不代表已映射到截图。

### 15.3 SDK / MCP

先做与现有技术栈一致的薄 SDK，把 session/epoch、帧资源、节点引用、错误和取消封装好。MCP 只在需要时添加，作为同一协议的适配器，不引入第二套授权和后端。

SDK 不自动重试结果不明的写操作，不自动切换到新默认会话，不静默把 stale node 替换成同名控件。外部模型可以自主选视觉或语义，不强制所有任务都先扫树。

### 15.4 与 VimalinxOS 的边界

保留 AgentSeat 对 GUI session、operation、receipt 和 intervention 的状态主权。提供可映射字段，供外部系统关联自己的工作线程和任务。不要复制外部调度数据库，也不要为统一概念重建整个 Agent 管理器。

## 16. 六阶段交付计划

| 阶段 | 交付内容 | 必须通过的关口 | 可并行工作 |
|---|---|---|---|
| P0 基线与合同 | 本地/公开差异、故障用例、真实环境清单、基准、协议 ADR | 事实/建议/已复现严格区分；结束时冻结首批指标 | 只读 AT-SPI 范围探针 |
| P1 可靠控制 | 非阻塞 IPC、会话校验、控制代际、可取消输入、所有权释放、诚实回执 | 慢连接不挡接管；长文本可停；旧请求不串；无假成功 | 私有总线生命周期验证、IME 现状探针 |
| P2 窗口与视觉 | 合成器真实事件、窗口注册、坐标变换、单次完成截图、移除高频宿主查询 | 真实弹窗与缩放正确；后台观察不切宿主；读取不抢焦点 | 人类 IME 路线验证 |
| P3 只读语义 | ApplicationScope、三只读接口、节点引用、预算/分页、隐私 | 同名宿主/封装不串；未知归属拒绝；大树和慢应用不阻塞 | 事件读取基础 |

| P5 使用体验与发布 | 按需捕获复用、IME 完整验收、可选 HUD 构建、移出旧特例、兼容/压力测试 | 真实应用矩阵、回归报告、诚实能力清单、可回滚升级 | 可选 MCP，不阻塞核心 |

### 16.1 第一个正式开发批次

先落地一个可执行故障 fixture，再处理：非阻塞请求读写、服务端 session 检查、控制代际、可取消 type、受限释放、window 空操作错误。用真实 GUI 展示“输入中人类接管 → 旧操作废弃 → 重新观察 → 新操作成功”。

根据实现耦合度，把合成器最终投递门禁与 daemon 取消放在同一可审查系列；不要仅完成 daemon 部分就宣称可靠接管已修好。

同时提交只读 AT-SPI 探针报告：实际 session bus/a11y bus、Registry、应用连接归属、节点覆盖、启动器退出后的存活、宿主同名实例隔离。探针不启用语义写，不改变宿主全局设置。

## 20. 发布定义

只有达到以下条件，才称为可靠的混合 Computer Use Runtime：

人类能接管且旧计划失效；写入不串会话或宿主实例；输入、语义调用和窗口操作回执真实；视觉观察及时且不过度耗资源；语义缺失时能退化；人类中文编辑实际可用；真实应用矩阵和性能结果可重复。

“已经有 AT-SPI”“已经支持 MCP”“已经能截屏点击”都不是单独的发布完成标准。

## 22. 应用自动适配：外部生成，运行时受限接入

### 22.1 目标与责任

在 P0–P5 主线之上增加独立的 A0–A3 适配交付线。目标是为语义不足的应用生成可重复验证、可撤销的适配包。日常操作复用已验证接口，不反复调用模型分析应用代码。

AgentSeat 本项目负责能力诊断、适配包合同、加载边界、语义来源、统一动作仲裁和验收 fixture。外部 Coding Agent 负责源码分析、补丁/插件生成及工具链工作；本项目不新增模型循环、反编译平台或外部调度器。助手里的自动适配入口和跨项目执行由 VimalinxOS 根协调者确定 owner；当前外部助手实现状态为 unknown，本计划不在其他注册项目落地。

本轮产出的是设计。任何工具包支持、插件入口与应用版本兼容性，都要对真实目标验证后才能列为支持。

|---|---|---|---|
| 1 | 已有语义但未启用 | 仅作用于目标实例的启动配置 | 实际节点、状态及事件可读；宿主全局环境不变 |
| 2 | 标准控件缺名称/状态/动作 | 最小组件、HTML/ARIA、QML 或 GTK 源码补丁 | 信息连接真实状态；保留键盘、焦点和原动作流程 |
| 3 | 自定义 Qt 控件且有可用接入点 | QAccessible 实现或兼容插件 | 加载机制、Qt/应用 ABI、对象生命周期和 GUI 线程正确 |
| 4 | 自绘界面且可读取真实对象模型 | 基于 AccessKit 或工具包的语义适配器 | 树、增量事件、动作和真实窗口可关联 |
| 5 | 无稳定状态或动作入口 | 报告未支持并使用现有视觉通道 | 视觉推断明确标注，不能宣称原生语义 |

Electron 官方说明可通过应用 API 开启 accessibility，网页语义仍需正确实现。[S16] 此 API 的存在不等于外部 runtime 能无条件调用任意第三方应用内部 API。Qt 支持无障碍接口及插件，但不意味着任意闭源控件的内部状态自动可见。[S17] AccessKit 接收应用提供的树更新和动作处理，不负责从任意应用恢复对象模型。[S18]

原生二进制分析保留为未来有明确目标时的深度手段，不属于首批适配功能。ASAR 解包也不保证可维护源码或可加载补丁存在；遇到打包、完整性或版本约束，记录具体阻塞，不通过全局关闭完整性检查解决。

### 22.3 适配包最小合同

第一版使用本地目录包，不建设远程市场、账号、后台更新服务或数据库。清单字段均为待实现设计：

- `schema_version`、`adapter_id`、适配包内容摘要。
- 目标应用版本和关键资源摘要；工具包版本、ABI、启动模式及支持的平台约束。
- 补丁、插件或启动配置及其装载入口；明确需要的文件修改、辅助进程和可执行代码。
- 支持的窗口、控件与动作范围，已知不支持项。
- 语义字段与真实组件/状态入口的映射证据，动作入口和事件来源。
- 验证步骤、运行环境、证据与测试结果，以及可重复的构建说明。
- 停用方式、原始资源摘要、回滚范围和数据兼容限制。

内容摘要用于发现变化和绑定已审核版本，不自动证明代码可信。适配包是可执行代码交付；清单里写“只读”不能阻止恶意插件调用应用内部函数，不能把它当作进程沙箱。

源码补丁优先作用于项目内隔离测试副本；交付测试副本放在 projects/AgentSeat/artifacts/smoke 或适当 artifacts 子目录，不新建第二个项目根。正式启用使用经确认的目标实例和安装方式，遵循既有 source/install 与 XDG 合同，不直接覆盖用户正在使用的应用包。具体安装路径在实现时按现有布局冻结。

### 22.4 语义来源与协议一致性

观察结果区分 `native`、`adapted`、`visual_inferred`，这是新增字段设计，不是现有 API。来源可以按节点或字段记录，避免给整个应用贴上一个过度概括的标签。

`adapted` 至少记录适配包 ID/摘要、目标版本、节点生命周期及状态映射来源。字段可能来自用户可见名称、应用模型或控件属性；不能把模型猜测写成实时 enabled/value。

优先通过工具包或 AccessKit 暴露标准 AT-SPI，再由现有语义桥消费。若必须采用外部侧车，先解决应用、总线连接和窗口关联；不能为了让它通过 ApplicationScope 而给任意同 UID 进程豁免，也不能把一个私有 JSON 服务称为已完成 AT-SPI 接入。

更新应来自应用状态变化，按需合并，遍历和事件资源遵守主线预算。完全没有真实入口时，只输出有帧版本的视觉定位，沿用坐标动作校验。

### 22.5 动作与暂停

Agent 发起的适配动作通过 agentseatd 的同一 act/授权入口，继承 session、epoch、节点代际、取消和回执规则。适配器不得提供给 Agent 一个可绕开该入口的独立命令端点。

补丁调用原来的用户交互处理入口，保留 disabled、校验、确认、撤销及错误路径，不以直接修改底层文件或调用内部提交函数冒充按钮行为。插件回调涉及 GUI 状态时遵守目标工具包线程约束。

标准 AT-SPI 本身可能被其他同 UID 辅助工具调用，加载到应用里的代码也拥有应用权限。因此这里只约束 AgentSeat 管理的调用路径，不承诺阻挡一切外部调用。已发给应用的语义动作仍遵守第 10.2 节的在途限制，暂停不等于事务回滚。

### 22.6 生成、验证、启用与更新

```text
诊断 → 选择最小路线 → 外部生成候选包 → 隔离实例验证
     → 记录兼容指纹和证据 → 按已有授权启用 → 日常复用
```

诊断只读。未支持的控件不会自动触发应用修改。启用前展示具体补丁范围、加载方式、已通过项目和回滚办法；已有授权覆盖明确目标和修改时不重复请求。当前提供计划不等于授权修改任意第三方安装应用。

版本或关键资源变化时，在加载前重新检查匹配；不匹配则停用适配并报告原因。视觉回退只用于后续明确选择的操作，不重放结果不明的适配动作。外部 Coding Agent 针对新版本生成候选包后重跑测试，不能按控件同名判定兼容。

原位热卸载通常不能保证撤回注入代码。第一版优先在下次受控启动时启用/停用；需要重启时保留用户未保存工作并说明影响。回滚恢复适配代码/配置，不承诺撤销已发生的业务动作或恢复全部应用数据。

### 22.7 分阶段依赖

| 阶段 | 依赖 | 交付与退出标准 |
|---|---|---|
| A0 诊断与包合同 | P0 基线；P3 前只做离线设计和 fixture | 分类现有/缺失语义，冻结本地包合同及证据形状；不加载生成代码 |
| A1 Electron 首个闭环 | P3 范围验证；写验收依赖 P4 | 自有或可修改测试应用：修复一个真实组件，读取状态、调用原动作、收到更新；启用/停用及版本不匹配可验证 |
| A2 Qt/QML 第二条路线 | A1 包生命周期通过；P4 | 使用最小可用 QML 补丁或 QAccessible 实现；仅在需要时验证插件路线，避免同时维护多套无必要方案 |
| A3 自绘与外部自动生成 | A1/A2 验收；外部 owner 明确 | AccessKit 真实模型样例；外部 Coding Agent 产生同合同适配包并通过同一验收，无人工隐藏修补 |

A0 可与主线设计同时开展，A1/A2 不阻塞 P1/P2。自动适配不是 vNext 核心发布的强制依赖；按完成的路线单独发布实验性能力。文中“并行”表示工作依赖可独立，不自动授权创建子 Agent。

### 22.8 适配验收增量

| 编号 | 用例 | 完成条件 |
|---|---|---|
| A-T01 | 只需启用现有能力 | 不改应用源码即可读到真实语义；诊断能解释启用方式 |
| A-T02 | 名称、禁用和选择状态 | 与真实 UI 同步；运行中变化后旧状态不会继续当作当前状态 |
| A-T03 | 按钮与确认框 | 语义动作进入原用户流程；确认框仍出现，不绕过校验 |
| A-T04 | 控件销毁重建 | 旧 node_ref 失效；同名节点不自动继承待执行动作 |
| A-T05 | 两个同版本同名实例 | 仅指定实例加载适配；读取和动作不串宿主 |
| A-T06 | 接管与在途动作 | 未发送动作取消；已发送动作如实报告可能副作用 |
| A-T07 | 版本/ABI/资源改变 | 加载前拒绝不兼容包；不自动修改新版错误位置 |
| A-T08 | 停用与回滚 | 移除适配后原应用路径可用；未保存工作受保护，回滚局限明确 |
| A-T09 | 人类视觉与键盘回归 | 原布局、焦点、快捷键、中文输入及工具包行为无意外退化 |
| A-T10 | 适配关闭/空闲/高事件频率 | 关闭无辅助运行成本；开启开销纳入 PSS/CPU/事件预算 |
| A-T11 | 无真实模型的画布 | 返回 visual_inferred 或 unavailable，不伪造状态和动作支持 |
| A-T12 | 外部生成复现 | 干净测试副本按包说明可复现构建、加载、测试、停用 |

先以自有 fixture 验证，再选一个明确可修改的真实应用检验兼容性。候选应用名称、版本、来源及允许的修改范围在 A1 开始前确定，不在计划阶段假定可改任意商业应用。

### 22.9 首次实施顺序与交接

后续功能实施先核对文首交付进展和当前协议合同，补齐待验收项，再进入尚未实施的 P4 或 A0 数据合同。不要跳过主线，直接把生成插件加载进用户常用应用。

交给外部助手 owner 的最小材料是目标应用诊断、包合同、允许的修改范围、构建/运行测试入口和验收结果格式。由 VimalinxOS 根协调者确定外部生成任务、用户入口和调度实现；AgentSeat 返回局部加载与验收事实，不代外部项目宣布功能完成。
